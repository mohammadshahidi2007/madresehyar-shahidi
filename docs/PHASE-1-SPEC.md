# مشخصات اجرایی فاز یک مدرسه‌یار شهیدی

وضعیت: تأییدشده برای شروع پیاده‌سازی  
نسخه: 1.0  
تاریخ: 2026-11-16  
مبنای معماری: Laravel + PostgreSQL + REST API

## 1. هدف
تبدیل نمونه فعلی استاتیک به زیرساخت سمت سرور با پایگاه داده مرکزی، احراز هویت با نام کاربری و مجوزهای سمت سرور. این فاز زیرساخت، حساب‌ها، نقش‌ها و ورود امن را تحویل می‌دهد؛ گردش‌کارهای آموزشی در فازهای بعدی ساخته می‌شوند.

## 2. تصمیم‌های قطعی نسخه اول

| موضوع | تصمیم |
|---|---|
| کاربران | مدیر مدرسه، معلم، دانش‌آموز |
| والدین | خارج از محدوده نسخه اول |
| شناسه ورود | نام کاربری یکتا |
| روش ورود | نام کاربری + گذرواژه |
| ایجاد حساب | فقط توسط مدیر مدرسه؛ بدون ثبت‌نام عمومی |
| بازیابی گذرواژه | فقط از طریق مدیر؛ صدور گذرواژه موقت |
| تغییر گذرواژه | کاربر پس از ورود با گذرواژه موقت باید گذرواژه خود را تغییر دهد |
| Backend | Laravel |
| Database | PostgreSQL |
| API | REST با پیشوند /api/v1 |
| معماری | Modular Monolith |
| نسخه فعلی | تا پذیرش و استقرار جایگزین حفظ می‌شود |

## 3. نقش‌ها و حدود دسترسی

### مدیر مدرسه — admin
- ایجاد، ویرایش، غیرفعال‌سازی و بایگانی حساب‌های معلم و دانش‌آموز
- تعیین نقش و اتصال حساب به پرونده معلم یا دانش‌آموز
- صدور گذرواژه موقت و اجبار تغییر آن در ورود بعدی
- مدیریت تنظیمات هویتی و دسترسی‌ها در محدوده مدرسه

### معلم — teacher
- مشاهده اطلاعات حساب خود
- دسترسی به کلاس‌ها و منابعی که به او تخصیص داده شده‌اند
- عملیات آموزشی در فاز یک پیاده‌سازی نمی‌شود

### دانش‌آموز — student
- مشاهده اطلاعات حساب خود
- در فازهای بعد فقط مشاهده پرونده و سوابق آموزشی متعلق به خودش
- پنل آموزشی در فاز یک پیاده‌سازی نمی‌شود

مجوزها در سمت سرور اعمال می‌شوند. مخفی‌کردن گزینه‌ها در رابط کاربری کنترل دسترسی محسوب نمی‌شود. هر درخواست باید نقش و دامنه منبع مورد دسترسی را بررسی کند.

## 4. مدل داده و قیود

### جدول users
فیلدهای پیشنهادی:
- id
- username با قید یکتایی در سطح پایگاه داده
- password برای هش گذرواژه؛ هرگز متن خام
- is_active
- must_change_password
- password_changed_at (nullable)
- last_login_at (nullable)
- created_at و updated_at

### جدول‌های نقش و پرونده
- roles: نقش‌های ثابت admin، teacher، student
- user_roles: رابطه کاربر و نقش؛ در نسخه اول هر حساب دقیقاً یک نقش اصلی دارد.
- teachers: پرونده معلم و پیوند یکتا به users
- students: پرونده دانش‌آموز و پیوند یکتا به users

حساب مدیر اولیه از طریق فرمان امن و مستند استقرار یا فرایند bootstrap ساخته می‌شود؛ هیچ نام کاربری یا گذرواژه پیش‌فرضی در کد یا مخزن قرار نمی‌گیرد. گذرواژه اولیه از ورودی امن محیط استقرار دریافت می‌شود و در log چاپ نمی‌شود.

### قواعد داده
- نام کاربری پس از نرمال‌سازی باید یکتا باشد؛ سیاست حروف بزرگ/کوچک و کاراکترهای مجاز در اعتبارسنجی واحد اعمال شود.
- گذرواژه با Hash API خود Laravel و الگوریتم امن پیکربندی‌شده هش شود.
- غیرفعال‌سازی حساب به‌جای حذف فیزیکی انجام شود.
- حذف حساب نباید سوابق آموزشی را به‌صورت آبشاری حذف کند.
- تمام تغییرات مدیریتی حساس دارای زمان و شناسه عامل انجام‌دهنده باشند.

## 5. جریان‌های کاربردی

### ایجاد حساب
1. مدیر احراز هویت می‌شود.
2. اطلاعات ضروری و نوع حساب را ثبت می‌کند.
3. سرور نام کاربری را نرمال‌سازی و یکتایی آن را بررسی می‌کند.
4. سامانه گذرواژه موقت تصادفی و قوی صادر می‌کند؛ مقدار خام فقط یک‌بار به مدیر نمایش داده می‌شود.
5. هش گذرواژه ذخیره و must_change_password=true می‌شود.
6. رویداد ایجاد حساب ثبت می‌شود.

ثبت‌نام عمومی، خودخدمتی و واردسازی Excel در این فاز نیستند.

### ورود
1. کاربر نام کاربری و گذرواژه را ارسال می‌کند.
2. اعتبارسنجی ورودی و محدودسازی نرخ درخواست اجرا می‌شود.
3. سرور حساب فعال را پیدا و گذرواژه را با هش ذخیره‌شده بررسی می‌کند.
4. برای خطای نام کاربری/گذرواژه پاسخ عمومی یکسان برگردانده می‌شود تا وجود حساب افشا نشود.
5. نشست امن ایجاد یا بازسازی می‌شود.
6. اگر must_change_password=true باشد، کاربر فقط به مسیر تغییر گذرواژه دسترسی دارد.
7. زمان آخرین ورود و رویداد امنیتی ثبت می‌شود.

### تغییر گذرواژه
- گذرواژه فعلی یا گذرواژه موقت معتبر و گذرواژه جدید دریافت می‌شود.
- حداقل طول و سیاست کیفیت گذرواژه در یک محل پیکربندی و آزمون می‌شود.
- پس از تغییر موفق، must_change_password=false و password_changed_at به‌روزرسانی می‌شود.
- نشست‌های دیگر کاربر باطل می‌شوند؛ نشست فعلی طبق سیاست نشست امن بازتولید می‌شود.

### بازیابی با کمک مدیر
1. مدیر هویت درخواست‌کننده را طبق رویه مدرسه بررسی می‌کند.
2. مدیر برای حساب موردنظر فرمان صدور گذرواژه موقت را اجرا می‌کند.
3. سامانه گذرواژه موقت تصادفی، یک‌بارنمایش و محدود به همان حساب صادر می‌کند.
4. مقدار هش‌شده ذخیره و must_change_password=true می‌شود.
5. نشست‌های قبلی حساب باطل می‌شوند.
6. رویداد بازنشانی شامل عامل، حساب هدف و زمان ثبت می‌شود؛ گذرواژه یا مقدار محرمانه در log ذخیره نمی‌شود.
7. کاربر در ورود بعدی ناچار به تعیین گذرواژه جدید است.

بازیابی پیامکی/ایمیلی و پیوند بازیابی خودکار در نسخه اول وجود ندارد.

### خروج
نشست سمت سرور باطل و کوکی نشست پاک یا منقضی می‌شود. درخواست‌های بعدی با نشست قبلی باید رد شوند.

## 6. قرارداد API فاز یک

| روش | مسیر | دسترسی | شرح |
|---|---|---|---|
| POST | /api/v1/auth/login | عمومی با rate limit | ورود |
| POST | /api/v1/auth/logout | احراز هویت‌شده | خروج |
| GET | /api/v1/me | احراز هویت‌شده | حساب و نقش فعلی |
| POST | /api/v1/auth/password | احراز هویت‌شده | تغییر گذرواژه |
| GET | /api/v1/admin/users | فقط مدیر | فهرست حساب‌ها |
| POST | /api/v1/admin/users | فقط مدیر | ایجاد حساب معلم/دانش‌آموز |
| PATCH | /api/v1/admin/users/{user} | فقط مدیر | ویرایش/غیرفعال‌سازی |
| POST | /api/v1/admin/users/{user}/reset-password | فقط مدیر | صدور گذرواژه موقت |

پاسخ API باید ساخت‌یافته و بدون جزئیات حساس باشد. هیچ endpoint مدیریتی نباید صرفاً به کنترل رابط کاربری متکی باشد.

## 7. الزامات امنیتی
- HTTPS در staging و production اجباری است.
- برای رابط و API هم‌مبدأ، نشست مبتنی بر کوکی امن Laravel ترجیح دارد؛ کوکی‌ها HttpOnly، Secure و SameSite مناسب داشته باشند.
- در صورت استفاده از کوکی/نشست، محافظت CSRF فعال و درست پیکربندی شود.
- پس از ورود و تغییر سطح دسترسی، شناسه نشست بازتولید شود.
- login و reset-password دارای rate limit باشند.
- خطای ورود نباید وجود یا عدم وجود نام کاربری را افشا کند.
- گذرواژه، کوکی نشست، توکن و گذرواژه موقت در log ثبت نشوند.
- دسترسی پایگاه داده از اینترنت عمومی مسدود باشد.
- secrets فقط در محیط امن میزبان/مدیریت secrets نگهداری شوند.
- آزمون‌های مجوز باید دسترسی بین‌کاربری و بین‌نقشی را پوشش دهند.
- داده واقعی دانش‌آموز در محیط توسعه، تست یا مخزن استفاده نشود؛ داده آزمون ساختگی باشد.

## 8. محیط‌ها و کیفیت تحویل
- محیط توسعه محلی، staging و production از هم جدا باشند.
- migrationها در کنترل نسخه باشند و اجرای آن‌ها قابل تکرار باشد.
- CI حداقل شامل نصب وابستگی‌ها، بررسی سبک کد و آزمون‌های خودکار باشد.
- خطاهای برنامه پایش شوند، بدون ثبت اطلاعات محرمانه.
- مستندات نصب، تنظیم متغیرهای محیطی، ساخت مدیر اولیه، پشتیبان‌گیری و استقرار ارائه شوند.
- GitHub Pages و نسخه استاتیک فعلی تا پذیرش نسخه جایگزین حفظ شوند.

## 9. آزمون‌های پذیرش
1. کاربر ناشناس به endpoint خصوصی دسترسی ندارد.
2. نام کاربری تکراری در سطح برنامه و DB رد می‌شود.
3. ورود با گذرواژه نادرست رد می‌شود و پاسخ، وجود حساب را افشا نمی‌کند.
4. حساب غیرفعال نمی‌تواند وارد شود.
5. محدودیت تلاش ورود اعمال می‌شود.
6. مدیر می‌تواند حساب معلم و دانش‌آموز بسازد؛ کاربر عادی نمی‌تواند.
7. معلم و دانش‌آموز به endpointهای مدیریتی دسترسی ندارند.
8. کاربر نمی‌تواند داده یا حساب کاربر دیگر را از مسیرهای خودخدمت مشاهده/تغییر دهد.
9. گذرواژه موقت در ورود بعدی تغییر اجباری دارد.
10. پس از reset مدیر، نشست‌های قبلی حساب باطل می‌شوند.
11. خروج، نشست قبلی را بی‌اعتبار می‌کند.
12. logها فاقد گذرواژه، گذرواژه موقت و شناسه نشست هستند.
13. آزمون‌ها با PostgreSQL اجرا می‌شوند و migration تازه از ابتدا موفق است.

## 10. خارج از محدوده فاز یک
- پنل و گردش‌کار حضور و غیاب، نمرات، تکالیف و امتیازها
- ثبت‌نام عمومی
- بازیابی پیامکی یا ایمیلی
- ورود یک‌بارمصرف (OTP) یا ورود اجتماعی
- حساب والدین
- واردسازی گروهی Excel
- مهاجرت خودکار localStorage به پایگاه داده عملیاتی
- استقرار نهایی قبل از انتخاب و ارزیابی محل میزبانی و الزامات حریم خصوصی

## 11. وابستگی‌ها و تصمیم‌های باز پیش از production
این موارد مانع طراحی و شروع توسعه محلی نیستند، اما پیش از انتشار عملیاتی باید تعیین شوند:
- تعداد کاربران هم‌زمان و برآورد ظرفیت
- کشور/منطقه محل نگهداری داده و الزامات قانونی/قراردادی
- ارائه‌دهنده میزبانی، دامنه و سیاست پشتیبان‌گیری
- تقویم و منطقه زمانی رسمی مدرسه
- رویه احراز هویت مدیر هنگام درخواست بازنشانی گذرواژه

## 12. تعریف پایان فاز
فاز یک زمانی پذیرفته می‌شود که همه آزمون‌های پذیرش بخش 9 موفق باشند، مستندات استقرار آماده باشند، secrets در مخزن نباشند و نسخه فعلی تا زمان تأیید جایگزین بدون اختلال حفظ شده باشد.
