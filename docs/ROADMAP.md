# نقشه راه اجرایی مدرسه‌یار شهیدی

این نقشه راه بر اساس حفظ نسخه فعلی و توسعه تدریجی روی زیرساخت ابری تنظیم شده است. زمان‌بندی قطعی پس از تعیین دامنه، ارائه‌دهنده میزبانی و ظرفیت توسعه مشخص می‌شود.

## فاز صفر — شناخت و طراحی
- [x] بررسی مخزن GitHub و فایل‌های موجود
- [x] تأیید وضعیت فعلی: رابط استاتیک و localStorage
- [x] انتخاب مسیر: حفظ نسخه فعلی و توسعه تدریجی
- [x] انتخاب اولیه: Laravel + PostgreSQL + میزبانی ابری
- [x] تهیه سند معماری اولیه
- [x] تعیین کاربران نسخه اول: مدیر، معلم و دانش‌آموز؛ والدین خارج از دامنه
- [x] تعیین ورود با نام کاربری و گذرواژه
- [x] تعیین ایجاد حساب فقط توسط مدیر و بازیابی گذرواژه با گذرواژه موقت صادرشده توسط مدیر
- [x] تهیه مشخصات اجرایی فاز یک
- [ ] انتخاب ارائه‌دهنده ابری پس از بررسی حریم خصوصی، محل داده و هزینه

**خروجی فاز:** دامنه نسخه اول و مشخصات اجرایی فاز یک تأیید شده است. انتخاب میزبان و آماده‌سازی production همچنان باز است.

## فاز یک — زیرساخت و احراز هویت
- [ ] ایجاد پروژه Backend با Laravel و تنظیم محیط local
- [ ] اتصال PostgreSQL و مدیریت migrationها
- [ ] ایجاد مدل users، roles، user_roles و پیوند پرونده معلم/دانش‌آموز
- [ ] ایجاد فرایند امن bootstrap برای مدیر اولیه؛ بدون اعتبارنامه پیش‌فرض در مخزن
- [ ] پیاده‌سازی ورود، خروج، نشست امن و rate limiting
- [ ] پیاده‌سازی تغییر گذرواژه و الزام تغییر پس از صدور گذرواژه موقت
- [ ] پیاده‌سازی مدیریت حساب‌ها فقط برای مدیر: ایجاد، ویرایش و غیرفعال‌سازی
- [ ] پیاده‌سازی صدور گذرواژه موقت توسط مدیر و ابطال نشست‌های قبلی
- [ ] پیاده‌سازی مجوزهای سمت سرور و آزمون جداسازی داده‌ها
- [ ] ایجاد CI برای آزمون‌ها و بررسی کد
- [ ] مستندسازی نصب، تنظیم secrets، استقرار و عملیات مدیر

**معیار پذیرش:** آزمون‌های مشخص‌شده در docs/PHASE-1-SPEC.md موفق باشند؛ کاربر ناشناس به API خصوصی دسترسی نداشته باشد و هر نقش فقط عملیات مجاز خود را انجام دهد.

## فاز دو — هسته مدیریت مدرسه
- سال تحصیلی، پایه، کلاس و درس
- پرونده دانش‌آموز و دبیر
- ثبت‌نام دانش‌آموز در کلاس
- تخصیص دبیر به کلاس/درس
- جست‌وجو، ویرایش، بایگانی و سوابق

**معیار پذیرش:** داده‌ها در پایگاه داده مرکزی ذخیره شوند و قواعد یکتایی و ارتباطی آزمون شده باشند.

## فاز سه — گردش‌کار آموزشی
- جلسه و رکورد حضور و غیاب
- ارزشیابی و ثبت نمره
- دفتر امتیازها و سوابق تغییر
- تکالیف و تحویل‌ها

**معیار پذیرش:** هر تغییر قابل ردیابی باشد و دبیر فقط در محدوده تخصیص خود عملیات انجام دهد.

## فاز چهار — پنل دانش‌آموز
- داشبورد شخصی
- مشاهده نمرات، حضور و غیاب و تکالیف
- مشاهده اطلاعیه‌ها
- طراحی واکنش‌گرا و دسترس‌پذیر

**معیار پذیرش:** آزمون‌های دسترسی نشان دهند دانش‌آموز فقط اطلاعات خودش را مشاهده می‌کند.

## فاز پنج — گزارش و خروجی
- گزارش فردی و کلاسی
- کارنامه و خروجی چاپی
- خروجی PDF و Excel
- نمودارهای عملکرد با تعریف روشن شاخص‌ها

**معیار پذیرش:** اعداد گزارش با داده‌های مرجع پایگاه داده تطبیق داشته باشند.

## فاز شش — امنیت، پشتیبان و آماده‌سازی عملیاتی
- بررسی امنیت و مجوزها
- محدودسازی نرخ درخواست و پایش خطا
- پشتیبان رمزگذاری‌شده و آزمون بازیابی
- سیاست نگهداری و حذف داده
- آزمون بار و سازگاری مرورگر/موبایل
- آموزش کاربران و برنامه پاسخ‌گویی به رخداد

**معیار پذیرش:** بازیابی موفق در محیط جداگانه و عبور از چک‌لیست امنیتی و پذیرش کاربر.

## فاز هفت — انتشار و توسعه بعدی
- استقرار نسخه عملیاتی
- مهاجرت کنترل‌شده داده‌های مجاز
- پایش و رفع اشکال
- سپس بررسی امکانات والدین، پیام‌رسانی، برنامه هفتگی و اعلان‌ها

## قواعد اجرایی
1. نسخه فعلی تا زمان آماده‌شدن جایگزین آزمایش‌شده حفظ می‌شود.
2. هر فاز با معیار پذیرش بسته می‌شود؛ صرفاً «کدنویسی تمام شد» کافی نیست.
3. هیچ داده واقعی دانش‌آموز در محیط توسعه یا مخزن Git قرار نمی‌گیرد.
4. کلیدها و رمزهای سرویس فقط در مدیریت secrets میزبان ذخیره می‌شوند.
5. قبل از مهاجرت، پشتیبان و روش بازگشت آزمایش می‌شود.
