# مدل داده هسته مدرسه‌یار شهیدی

این سند مدل اولیه پایگاه داده را برای فاز هسته مدیریت مدرسه ثبت می‌کند. همه داده‌های آزمون باید ساختگی باشند.

## جداول نسخه اول

| جدول | کاربرد | قیدهای مهم |
|---|---|---|
| `academic_years` | سال تحصیلی | نام یکتا، تاریخ شروع و پایان، شاخص سال فعال |
| `classrooms` | کلاس در یک سال تحصیلی | پایه ۷ تا ۹ در لایه اعتبارسنجی، یکتایی سال + پایه + بخش |
| `students` | پرونده پایه دانش‌آموز | کد دانش‌آموز یکتا، نام و نام خانوادگی |
| `subjects` | فهرست درس‌ها | کد درس یکتا |
| `classroom_student` | عضویت/ثبت‌نام دانش‌آموز در کلاس | کلید خارجی، یکتایی دانش‌آموز و کلاس، تاریخ ورود/خروج و وضعیت |

## تصمیم‌های حریم خصوصی

- در این مرحله کد دانش‌آموز شناسه داخلی مدرسه است؛ کد ملی، نشانی، تلفن، اطلاعات پزشکی و سایر داده‌های حساس در مدل پایه ذخیره نمی‌شوند.
- تاریخ تولد نیز تا وقتی نیاز عملیاتی و مبنای نگهداری آن تأیید نشده، اضافه نمی‌شود.
- حذف سال تحصیلی یا کلاس در حال حاضر به‌صورت آبشاری روی رکوردهای وابسته تعریف شده؛ پیش از استفاده واقعی باید سیاست بایگانی/حذف و نگهداری سوابق نهایی شود.
- نام پایه و بخش باید در لایه درخواست اعتبارسنجی شوند؛ مقدار پایه فقط ۷، ۸ یا ۹ پذیرفته شود.
- همه روابط و محدودیت‌های کلیدی باید در PostgreSQL نیز آزموده شوند؛ موفقیت SQLite به‌تنهایی اثبات سازگاری کامل PostgreSQL نیست.

## خارج از دامنه این migration

احراز هویت، کاربران، نقش‌ها، تخصیص دبیر، حضور و غیاب، ارزشیابی، نمرات و تکالیف در migrationهای بعدی و پس از تثبیت قواعد دامنه اضافه می‌شوند.
